# Catalog Automation

> Auto-generated metadata for all 539 scripts — how it works and how to use it.

## Overview

`scripts/.catalog/metadata.json` is the machine-readable index of every
`scripts/**/*.ps1` file in the repository. It is generated by
`tools/Build-Catalog.ps1` and consumed by `Invoke-Umbrella.ps1` (interactive
launcher) and CI.

## Schema

```json
{
  "$schema": "https://raw.githubusercontent.com/Carme99/bug-free-umbrella/main/scripts/.catalog/metadata.schema.json",
  "version": "1.0.0",
  "generated": "2026-08-20T12:00:00.0000000+01:00",
  "totalScripts": 539,
  "scripts": [
    {
      "path": "endpoints/intune/reporting/Get-DeviceComplianceReport.ps1",
      "name": "Get-DeviceComplianceReport.ps1",
      "category": "endpoints/intune/reporting",
      "synopsis": "Exports all non-compliant devices from Intune ...",
      "description": "Detailed description truncated to 200 chars ...",
      "tags": ["intune", "compliance", "report"],
      "parameters": [
        { "name": "OutputPath", "type": "String", "mandatory": false }
      ],
      "hasCmdletBinding": true,
      "requiresModules": ["Microsoft.Graph.Authentication"],
      "functionsExported": ["Get-DeviceComplianceReport"]
    }
  ]
}
```

Field notes:

| Field | Description |
|---|---|
| `path` | Relative path without `scripts/` prefix, forward slashes |
| `category` | Directory portion of `path` (e.g. `endpoints/intune/reporting`) |
| `synopsis` | `.SYNOPSIS` text, or first comment line, or fallback |
| `description` | `.DESCRIPTION` truncated to 200 characters |
| `tags` | Keywords extracted from synopsis |
| `parameters` | Param block entries with `name`, `type`, `mandatory` |
| `hasCmdletBinding` | Whether `[CmdletBinding()]` is present |
| `requiresModules` | Parsed `#Requires -Modules` values |
| `functionsExported` | Top-level function definitions in the file |
| `totalScripts` | Must equal `find scripts -name '*.ps1' | wc -l` |

The `scripts` array is sorted by `path`.

## Build-Catalog.ps1

### Regenerate

```powershell
pwsh -File tools/Build-Catalog.ps1
```

Scans all `scripts/**/*.ps1`, parses each file via
`[System.Management.Automation.Language.Parser]::ParseFile` (AST), extracts
comment-based help with regex, detects `CmdletBinding`, parameters,
`#Requires` modules and functions, derives `category` and `tags`, and writes
`scripts/.catalog/metadata.json` as pretty-printed UTF-8 JSON.

### Validate (CI gate)

```powershell
pwsh -File tools/Build-Catalog.ps1 -Validate
```

Compares the on-disk `metadata.json` with a freshly generated copy
(ignoring the `generated` timestamp). Exits `0` if up to date, `1` if stale.
Use in CI to enforce that contributors regenerate the catalog.

### Verbose

```powershell
pwsh -File tools/Build-Catalog.ps1 -Verbose
```

Per-file progress via `Write-Verbose`.

## Invoke-Umbrella.ps1

Interactive launcher at the repository root.

### List all scripts

```powershell
pwsh -File ./Invoke-Umbrella.ps1 -List
pwsh -File ./Invoke-Umbrella.ps1 -List | head
```

### Search (fuzzy, case-insensitive)

```powershell
pwsh -File ./Invoke-Umbrella.ps1 -Search intune
pwsh -File ./Invoke-Umbrella.ps1 -Search azure
```

Matches against `path`, `synopsis` and `category`.

### Filter by category

```powershell
pwsh -File ./Invoke-Umbrella.ps1 -Category endpoints/intune
pwsh -File ./Invoke-Umbrella.ps1 -Category endpoints/intune -List
pwsh -File ./Invoke-Umbrella.ps1 -Search health -Category security
```

Prefix or substring match on `category`.

### Interactive picker

```powershell
pwsh -File ./Invoke-Umbrella.ps1 -Interactive
pwsh -File ./Invoke-Umbrella.ps1 -Search intune -Interactive
```

Uses `Out-GridView` when available, otherwise a numbered console menu.
After selection it shows synopsis, required modules (with availability check
via `Get-Module -ListAvailable`), parameter list, a `Get-Help` preview and
offers to invoke with `-WhatIf`.

### Validate only (no invoke)

```powershell
pwsh -File ./Invoke-Umbrella.ps1 -Search azure -ValidateOnly
```

Shows details for matched scripts without prompting to invoke.

### Help

```powershell
Get-Help ./Invoke-Umbrella.ps1 -Detailed
Get-Help ./Invoke-Umbrella.ps1 -Examples
```

## CI Integration

Add to a workflow:

```yaml
- name: Validate catalog
  run: pwsh -File tools/Build-Catalog.ps1 -Validate
```

If the step fails, run `pwsh -File tools/Build-Catalog.ps1` locally and commit
the updated `scripts/.catalog/metadata.json`.
